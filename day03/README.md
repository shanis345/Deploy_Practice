2026-09-27 실습 3-1~3-5·화면 관찰·자원 정리를 완료했고 사용자가 전체 완료를 확인했다. 별도 자기점검 5문항을 문답으로 평가한 기록은 없다.

| 단계 | 수행한 작업 | 실제 확인 결과 |
|---|---|---|
| 3-1 이미지 관찰 | history·inspect·dive로 기존 이미지 분석 | agent:0.1.0의 8개 파일 레이어, OS·의존성·앱 코드 구성 관찰 |
| 3-2 보안 설정 점검 | id·파일 쓰기·읽기 전용·tmpfs·헬스체크 정의 확인 | UID 10001 실행, /etc 쓰기 거부, read-only 쓰기 거부, tmpfs 쓰기 성공, /healthz 정의 |
| 3-3 취약점 개선 | Trivy 초기 검사 → 베이스 변경 빌드 → 재검사 | HIGH 95·CRITICAL 9 → HIGH 44·CRITICAL 0. 수정 버전 미제공 항목 제외 시 0건 |

| 3-5 반입 초안 | 이미지 식별자·설정·스캔 결과·근거 문서화 | IMPORT-PACKAGE.md 작성. 미검증 항목과 고객사 승인 필요 사항 명시 |
| 화면 관찰·정리 | lazydocker에서 새 이미지 확인, 임시 산출물 정리 | agent:0.2.0 181.28MB, 두 agent 이미지 보존, agent 컨테이너·leak:1 부재 |

최종 이미지 agent:0.2.0은 python:3.12.14-slim 기반이며 Python 3.12.14·Debian 13.7·linux/amd64다. 새 이미지 id 실행에서도 UID 10001·GID 0을 확인했다.

배운 구분: 앱 프로세스의 OS 권한과 로그인 사용자별 인가는 다르다. 스캔 정상 종료와 취약점 0건은 다르다. 수정 버전 미제공 필터와 실제 위험 해소는 다르다. 실습 자원 정리와 비밀의 복구 불가능한 삭제도 다르다.

이번 결과는 사전 점검 실습이며 실제 고객사 심의·반입·운영 배포 완료를 뜻하지 않는다. 전체 결과·한계는 SESSION과 반입 초안에 보존한다.
