# 부록 E — 신청서·보안 협의 패키지 템플릿

복사해서 고객사 양식에 옮겨 적는 용도입니다. 고객사 양식이 더 단순하면 빠진 항목을 "특이 요청사항"에 넣으세요. `skeleton/docs/`에 마크다운 파일로도 들어 있습니다.

## E-1. VM 신청서

```text
[신청 개요]
  용도            : AI 에이전트 파일럿 (프로젝트명: ______)
  기간            : YYYY-MM-DD ~ YYYY-MM-DD (파일럿 종료 시 회수)
  담당            : (FDE) ______ / (현업) ______

[VM 사양]
  수량            : 1 (파일럿) — 정식 전환 시 2 이상
  vCPU / 메모리    : 4 vCPU / 8 GB   (사내 모델 호스팅 시 GPU 노드 별도)
  디스크           : 100 GB (컨테이너 이미지 20GB + 로그 + DB)   ← 이미지 GC 방지를 위해 여유
  OS              : RHEL 9.x 또는 Ubuntu 22.04 (고객사 표준 템플릿)
  배치 존          : 업무망 (DMZ 아님)   포트그룹: ______
  HA 적용          : 요청 (파일럿은 선택)
  백업/스냅샷       : 배포 전 스냅샷 1회 요청

[특이 요청사항 — 반드시 기재]
  1. Docker Engine (또는 containerd/Podman) 설치 허용 및 설치 주체: ______
  2. sudo 권한 (또는 docker 그룹) 부여: 도커 데몬 설정(프록시·로그 로테이션·DNS) 목적
  3. 인터넷 아웃바운드: 사내 프록시 경유 (주소·포트: ______, 인증: 유/무)
  4. 사내 패키지 미러 주소: pip ______ / yum·apt ______
  5. 사내 CA 인증서 파일 제공 요청 (TLS 검사 환경인 경우)
  6. 서버 접근 방식: SAC 경유 시 파일 전송 방법·세션 타임아웃 확인
  7. 사전 설치 보안 에이전트(EDR 등)의 컨테이너 런타임 예외 처리 여부
  8. NTP / 타임존 (Asia/Seoul) / 사내 DNS 서버·도메인 접미사
  9. 도커 기본 대역(172.17.0.0/16~)과 사내 대역 충돌 여부 확인 요청
```

## E-2. 방화벽 정책 신청서

```text
[신청 개요]  용도: AI 에이전트 파일럿   기간: ~ YYYY-MM-DD (종료 시 전 정책 회수)   별첨: 데이터 흐름도 1장

 #  출발지                        목적지                         포트/프로토콜  용도                     방향       기간
 1  사내 사용자 PC 대역 (10.10.0.0/16)  GW-VM (DMZ, 10.1.1.10)          443/TCP    사용자 웹 접근           인바운드   ~종료일
 2  GW-VM (DMZ, 10.1.1.10)          AGENT-VM (업무망, 10.20.5.11)     8080/TCP   리버스 프록시 → 에이전트   DMZ→내부   ~종료일
 3  AGENT-VM (업무망)               DB-SVR (DB존, 10.30.1.5)          5432/TCP   조회 전용 계정 ro_agent    내부→DB    ~종료일
 4  AGENT-VM (업무망)               ERP-API (업무망, 10.20.3.20)      443/TCP    업무 데이터 조회          내부       ~종료일
 5  AGENT-VM (업무망)               사내 프록시 (10.20.0.8)           3128/TCP   LLM 호출 아웃바운드        아웃바운드  ~종료일
 6  AGENT-VM (업무망)               사내 레지스트리 (10.20.0.30)      443/TCP    컨테이너 이미지 수신       내부       ~종료일
 7  AGENT-VM (업무망)               로그 수집 서버 (관리망, 10.99.1.7) 9200/TCP   감사 로그 전송            내부→관리망 ~종료일

[별첨 2 — #5 프록시 화이트리스트 등록 요청]
  목적지 FQDN: <llm-endpoint>:443  (1개. 게이트웨이 경유로 단일화)
  IP가 아닌 FQDN 기반 허용 요청 (클라우드 API는 IP 가변)

[별첨 3 — 최소 권한 근거]
  #3: 읽기 전용 계정, 스키마 ______ 만. 쓰기 권한 없음 (verify.sh 항목 4로 검증)
  #2: 게이트웨이 → 에이전트 단일 포트. 에이전트 → DMZ 역방향 없음
  #5: 에이전트 직접 아웃바운드 없음. 게이트웨이만 프록시 경유 (verify.sh 항목 3·7)

[회수] 파일럿 종료일에 전 정책 회수. 연장 시 재신청.
```

!!! note
    출발지는 **VM IP**(또는 고객사 관례에 따라 대역)로 적습니다. 컨테이너 IP는 적지 않습니다(NAT). 쿠버네티스면 노드 대역 또는 egress IP — 플랫폼팀에 확인.

## E-3. 보안 협의 패키지

보안성 검토에 제출하는 묶음입니다. 이 다섯 절이 갖춰지면 검토 왕복이 줄어듭니다.

```text
1. 데이터 흐름도
   사용자 PC ─(1)─▶ [DMZ] 게이트웨이 ─(2)─▶ [업무망] 에이전트 ─(3)─▶ [DB존] DB (조회 전용)
                                                  │─(4)─▶ [업무망] ERP API
                                                  └─────▶ [업무망] LLM 게이트웨이 ─(5)─▶ 사내 프록시 ─▶ 외부 LLM (FQDN 1개)
                                                                    └─▶ [관리망] 감사 로그 DB (7)
   (번호 = 방화벽 신청서 행 번호)

2. 외부 전송 데이터
   - 전송 주체: LLM 게이트웨이만. 에이전트는 인터넷 경로 없음 (네트워크 분리/NetworkPolicy로 강제, verify.sh #3)
   - 전송 내용: 사용자 질문 + 시스템 프롬프트 + 조회 결과 요약. 개인정보 필드 마스킹 규칙: 별첨
   - 목적지: <llm-endpoint>:443 1개. 제공사 데이터 미보관(ZDR) 계약: 유/무
   - 국외 이전: 유/무 → 개인정보 포함 시 동의·고지 검토

3. 기록
   - 감사 로그: 호출자(가상 키·사용자)·시각·모델·토큰·비용·성공 여부. 보관 __년. 저장소: 관리망 DB
   - 프롬프트 원문: (미보관 / 해시·길이만 / 암호화 보관 __일) 중 합의
   - 애플리케이션 로그: JSON, 개인정보·원문 미포함, 사내 로그 시스템 전송
   - TLS 검사 장비의 로그 보관 정책: 확인 요청 (원문이 몇 벌 남는가)

4. 통제
   - 이미지: non-root(UID 10001), 취약점 CRITICAL 0 (리포트 첨부), SBOM 첨부, 비밀 미포함, 다이제스트 ______
   - 접근: DB 조회 전용 계정, 게이트웨이 키 인증, 등록 모델만 호출 가능. 사용자 인증은 정식 전환 시 SSO
   - 네트워크: 존 분리 + 방향성 정책(NetworkPolicy YAML 첨부), 화이트리스트 프록시, 아웃바운드 목적지 1개
   - 검증: verify.sh 15항목 결과 첨부

5. 회수
   - 파일럿 종료 시: 방화벽 정책 회수, 가상 키 폐기, 감사 로그 이관, 이미지·볼륨 삭제 확인서
```
