## 핵심 메시지와 배운 것
**여러 프로그램을 함께 실행하는 것과 장애에도 안정적으로 운영하는 것은 다르다.** Compose로도 실제 운영은 가능하지만, 운영 요구에 맞는 감시·복구·백업 등의 준비가 필요하다.

| 배운 것 | 쉽게 설명하면 | 이번 실습의 근거 |
|---|---|---|
| Compose | 여러 프로그램의 실행·연결 방법을 적어 둔 실행 설명서 | nginx·agent·PostgreSQL을 각각의 컨테이너로 함께 기동 |
| 자동 재시작의 한계 | 꺼진 프로그램을 켜는 것과 켜진 채 멈춘 프로그램을 복구하는 것은 다름 | 프로세스 종료는 자동 복구, 무응답은 unhealthy 표시 후 수동 복구 |
| 정상 판정의 범위 | 한 프로그램의 정상 응답이 전체 시스템의 정상을 보장하지 않음 | DB가 중단돼도 agent의 healthz는 정상 |
| 프로그램과 설정 분리 | 프로그램을 다시 포장하지 않고 업무 지침을 교체 | 외부 프롬프트 변경·원복을 재빌드·재시작 없이 반영; 앱의 재적재 기능 필요 |
| 환경변수 | 같은 프로그램에 환경별 설정값을 전달 | 공개 더미 값의 최종 설정 치환 확인; 암호화 기능과는 별개 |
| 컨테이너와 데이터 분리 | 프로그램을 철거해도 데이터 보관함은 유지 가능 | compose down 후 day05_pgdata 볼륨 존재 확인; 저장 데이터의 복원 시험은 별도 |

운영에서는 상태 표시와 실제 기능을 함께 확인하고, 장애 감지와 복구를 별도로 설계해야 한다. 로그 크기·보관 수 제한도 필요하다. 이번 구성에는 max-size=10m·max-file=3이 설정돼 있지만 실제 로그 순환을 유발하는 시험은 하지 않았다.
